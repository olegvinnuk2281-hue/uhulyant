# Ухилянт v27 — установка и проверка

**Основа:** полная версия Codex v26 RC5 из присланного архива «Новая папка.zip». Это **полная сборка**, а не новая игра с нуля. Существующие учётные записи и таблицы сохраняются.

## Установка

1. Сделай резервную копию исходного репозитория GitHub и **экспорт таблицы Supabase `players`** до обновления.
2. Распакуй `Uhilyant_v27_CODEX_FULL.zip` и замени файлы в **корне** своего репозитория.
3. Не удаляй `players`, не пересоздавай проект Supabase, не меняй логин пользователей и не перезаписывай Render Environment. Файл `.env` с настоящими секретами не входит в сборку.
4. Для локальной проверки: Node.js 18+, `npm install`, `npm test`, `npm start`. Для Render выполни Commit & Push и дождись завершения деплоя.
5. Открой Telegram Mini App и **на тестовом аккаунте** проверь вход, ежедневное колесо, смену имени, покупку костюма, успешную и неуспешную смену работы, ловлю ТЦК, восстановление после перезапуска/закрытия Telegram. Только после этого подключай игроков.

## Чтобы бесплатный Render не засыпал

В проект добавлен внешний heartbeat на `/healthz`: GitHub Actions вызывает его каждые 10 минут, а `npm run keepalive` можно запустить на другом постоянно включённом компьютере или сервисе.

1. Добавь проект в GitHub и отправь изменения в его ветку по умолчанию. Открой **Settings → Secrets and variables → Actions → Variables**.
2. Создай repository variable `KEEPALIVE_URL` со значением базового публичного адреса игры, например `https://имя-сервиса.onrender.com` (без `/healthz`).
3. Убедись, что Actions включены; workflow `Keep the game server responsive` должен запускаться по расписанию.

Разовый запуск workflow делает один пинг и завершается; он не держит runner занятым. Пинг помогает бесплатному сервису оставаться прогретым, пока расписание выполняется. GitHub может задерживать запуски, а бесплатный Render может перезапустить сервис и ограничивает месячные часы. Для надёжной постоянной работы нужен платный always-on план Render. Тариф здесь не меняется, проект не публикуется.

## Новые механики

- **Две крайние вакансии:** чайная с бронью (12 виртуальных ₴ / смена, **1%** риск задержания) и высокооплачиваемый ночной курьер без брони (980 ₴, **60%** риск). Между ними — ещё восемь вакансий с разной оплатой, риском и требованиями. Дистанционные тексты: 52 ₴, риск 0%.
- **Серверная рабочая смена:** срок `startedAt/endsAt` сохраняется в базе до ответа об успехе; при выходе из Telegram отсчёт не перезапускается, получить оплату можно один раз. Результат риска на старте определяет серверный генератор случайных чисел.
- **Анимации работы:** ноутбук и текст, мытьё пола, перенос ящиков, курьерский велосипед, фонарик охраны, ремонт инструментом, стройка; рисуется тот же герой, что и в самой игре, с надетой одеждой.
- **Голод и питание:** сытость падает на три единицы за час серверного времени даже офлайн. Магазин: 55 ₴, 22% риск ТЦК. Доставка домой: 125 ₴, 0% риск. Нужна сытость не ниже 10 для работы. Между приёмами пищи двухминутный перерыв.
- **Задержания ТЦК:** шесть названий событий, серверный урон здоровью и сохранение состояния ТЦК. Анимированный бусик. Риск профессии/вылазки отображается до начала; действующая бронь обнуляет фактический риск. Во всех перечисленных шансах речь о **вымышленной игровой механике**, не о реальной статистике.
- **7 комплектов одежды:** добавлены «Мандрівний механік» и «Тихий нічний дозорець». Полный комплект даёт небольшой серверный бонус к заработку или опыту. Два новых варианта татуировок и переключатель сигареты есть в редакторе персонажа.
- Купленная копия биты, монтировки или цепи расходуется после одного удара; кулак, нога и кирпич остаются без ограничений. В рейдах бригадой можно выбрать любого босса, если хватает ключей.
- **Соревнование:** недельная лига разделена на шесть дивизионов по уровню; показываются место игрока во всём дивизионе, ближайший соперник, таблица друзей и рейтинг бригад. В воскресенье результаты остаются видны после закрытия раунда.
- **Цель бригады на неделю:** засчитанные сервером смены и удары добавляют общие очки. На рубежах 300, 1 000 и 2 500 очков бригада автоматически получает ключ; вклад участников и позиция команды показаны в игре.
- Отступы Telegram берутся из `contentSafeAreaInset`, если клиент его поддерживает; старые клиенты используют отдельный fallback. На главном экране персонаж отображается во весь рост.
- Кнопка побега при задержании всегда находится на игровой сцене. Домашние действия собраны в три блока; на узком экране кнопки текущей работы переносятся строками.
- Музыка и звуки включаются в «Настройках»; плавающие переключатели не закрывают шапку или сцену.
- Удалённая работа с текстами и модерацией показывает короткую анимацию героя за ноутбуком; выбранная причёска видна под кепкой, каской и каптуром.
- **Изменение ника:** в профиле кнопка ✎, 3–20 символов (буквы, цифры, `_`), проверка уникальности, бесплатно раз в 7 суток. Данные авторизации/Telegram ID остаются прежними. Сохранение подтверждается базой.
- **Интерфейс:** более округлые карточки, крупнее иконки, описание наград и риска; Telegram safe area применяется без повторного сложения отступов, а кнопки игровых действий показывают короткие визуальные отклики и мультяшные звуки.

## Проверки перед выпуском

- `npm test`: **36/36 проверок пройдены**. Проверяются серверные сохранения и откат при сбоях, бой и расход оружия, недельная лига, награды бригад, Telegram safe area, сценарий побега, кадр персонажа в полный рост, ноутбук для работы, и одноразовая анимация заезда бусика.
- `node --check`: все JS-файлы проекта прошли проверку синтаксиса.
- В локальном браузере визуально проверены 320×568, 390×844, 844×390 и 1366×768: нет горизонтального переполнения, персонаж помещается в сцене, кнопка побега не перекрыта бусиком, а его высота соответствует короткой альбомной сцене.
- Анимация задержания визуально проверена в изолированной локальной копии страницы с тестовым состоянием, без входа и API. Обычный локальный маршрут остаётся за входом/регистрацией; новый аккаунт не создавался, серверный захват и повторное подключение не проверялись.
- Отступ старых клиентов Telegram визуально смоделирован резервом 92 px при 390×844: шапка начинается ниже верхней зоны, переполнения нет. Это не заменяет проверку внутри реальных Telegram-клиентов.
- Архив проверен чтением всех записей; секретный `.env` исключён, `.env.example` включён.

**Граница проверки:** ПК-подобный браузер проверен локально; Telegram-клиенты iOS/Android, живое задержание после реального входа и подключённый keepalive требуют ручной проверки. В репозитории нужно задать Actions variable `KEEPALIVE_URL` с публичным адресом игры. На Render и Supabase изменения не выкладывались.

## Важно: ограничения архитектуры Codex v26

Большинство **новых** действий v27 подтверждаются Supabase до ответа пользователю. Старый шестибоссовый бой пока рассчитывается в клиенте, но сервер проверяет общий прирост урона и расход купленных копий перед сохранением; друзьям отправляется только урон из принятого сервером сохранения, один раз. Остальные старые подработки и ТЦК всё ещё частично используют клиентскую логику и последующую синхронизацию, поэтому абсолютное «сохранение каждой миллисекунды при обрыве связи» гарантировать нельзя. Нужно сохранить однопроцессный Render: архитектура очереди не рассчитана на несколько одновременно пишущих экземпляров сервера. Полное объединение старой шестибоссовой системы с тремя бригадными боссами — отдельный будущий этап.
