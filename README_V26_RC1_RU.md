# Ухилянт — исправления v26, тестовая сборка RC1

Это рабочая промежуточная сборка на основе присланной v25.1. Все этапы большого задания пока НЕ завершены. На живые Render и Supabase изменения не загружались.

## Что изменено

- Мобильная раскладка: компактная сцена, доступное нижнее меню, прокрутка дополнительных разделов, размеры кнопок, safe area и высота окна Telegram/visualViewport.
- Единые гривны: основной профиль хранит баланс, world.cash отображает то же значение. При первом успешном запросе старые uah и world.cash складываются один раз; отметка economyV26 предотвращает повторение. Пример: 150 + 500 = 650. Для нового персонажа остаётся 150.
- Все изменения профилей в API определяются сравнением состояния и записываются одним upsert в существующую таблицу players до ответа об успехе. Совместный удар сохраняет владельца босса и атакующего; награда сохраняет участников вместе. При сообщённой базой ошибке изменения в памяти откатываются.
- Устаревшая версия денежного баланса не может перезаписать актуальный баланс. Конфликт возвращает серверный профиль; несохранённые локальные действия конфликтующей вкладки могут быть отменены.
- Регистрация и выдача новой сессии подтверждаются после сохранения. Если база не загружена, API возвращает 503.
- Клиент отправляет локальные изменения после паузы 450 мс, повторяет фоновую синхронизацию и сохраняет при скрытии страницы. Ошибка сети оставляет отметку несохранённых данных. pagehide использует keepalive.
- Новости отправляются подписчикам после записи изменений, а не до неё.
- Серверные сроки новой смены и колеса продолжают работать после повторного входа; повторное получение одной зарплаты блокируется.

## Проверки

Девять автоматических тестов с имитацией Supabase: однократная миграция, отсутствие лишнего стартового баланса, первое сохранение персонажа, отказ базы и откат, устаревшая вкладка, ошибка регистрации, совместный удар, смена после перезапуска и однократная выплата, колесо после перезапуска.

Chrome: 320×568, 360×640, 390×844, 412×915, 768×1024, 1366×768 и 844×390. Нижнее меню помещается, горизонтального переполнения и ошибок JavaScript не обнаружено. Отдельно проверены создание и сохранение персонажа, открытие улицы и казино на 320×568. Это браузерная проверка, не тест реального Telegram на iOS/Android.

## Установка

1. Сохранить резервную копию таблицы players перед миграцией балансов.
2. Заменить файлы проекта содержимым архива, сохранив переменные окружения Render. Настоящего .env в архиве нет.
3. Установить зависимости: npm install. Проверить: npm test. Запуск: npm start.
4. Существующая таблица players (id, data) остаётся прежней. Новые поля находятся внутри JSON data; отдельный SQL для этой сборки не нужен.
5. Запускать один экземпляр Node/Render. Данная архитектура использует память одного процесса и последовательную очередь запросов. Она пока не поддерживает несколько серверов, работающих с одной базой.
6. После установки проверить вход Telegram, покупку, работу, казино и повторный вход в тестовом аккаунте на настоящей Supabase.

## Что остаётся по полному заданию

- Перенос старых локальных действий работы, выпадения наград, ТЦК, освобождения, восстановления энергии и откатов в серверные команды. Сейчас сервер проверяет присылаемый прогресс, но не исполняет все эти действия сам.
- Объединение шести основных и трёх бригадных боссов в одну систему; уровни доступа, новая последовательность ключей, журнал урона, добивание, редкий дроп и сезонные рейтинги.
- Новые сценарии ТЦК/улицы, серверная командная операция освобождения и новые анимации сцен.
- Полный единый профиль прогресса: карьерный XP в world.xp остаётся отдельным показателем от XP уровня персонажа, инвентари основной игры и дополнительного мира пока отдельные.
- Фильтры новостей по друзьям/категориям, доставка между несколькими серверами.
- Полная художественная унификация и проверка всех экранов, клавиатуры, реальных safe area и Telegram-клиентов.
- Проверка настоящего бота, Render и Supabase. Текущие тесты используют имитацию базы.

## Границы сохранения

Подтверждённые сервером изменения записаны в базу. Локальное действие до успешной отправки ещё может потеряться при принудительном закрытии. Отключение сети и неоднозначный обрыв соединения во время записи не дают абсолютной гарантии результата: перед повторной покупкой или ставкой нужно обновить профиль. Полной идемпотентности покупок/ставок и общей координации нескольких серверов пока нет.

В этой небольшой однопроцессной версии запросы сериализованы, а поиск изменённых профилей использует снимок игроков. Для большой аудитории требуется переход к транзакционным серверным командам и операциям базы на уровне отдельных игроков; нагрузочный тест не проводился.
